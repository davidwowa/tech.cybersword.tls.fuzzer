# TLS Fuzzer Agent Notes

## Project Goal

This project is a Java TLS fuzzer for TLS 1.2 and TLS 1.3. It generates byte-level TLS records and malformed/boundary vectors, sends them to a configured TLS target, and exposes current run status through desktop and browser dashboards.

## Current Runtime Defaults

Configuration lives in `tech.cybersword.tls.fuzzer.properties`.

- Target host: `localhost`
- Target port: `31337`
- Requests per legacy fuzzer job: `100`
- Worker threads: `4`
- Socket read timeout: `100` ms
- Random fixed-array size: `1000`
- Random variable-array range: `0..10000`
- Browser dashboard: enabled
- Browser dashboard URL: `http://localhost:8080/`
- Browser dashboard HTTPS: disabled by default, enabled with a Java keystore path/password

For local manual testing, a matching OpenSSL server can be started with:

```bash
openssl req -x509 -newkey rsa:2048 -keyout /tmp/tls-fuzzer-key.pem -out /tmp/tls-fuzzer-cert.pem -days 1 -nodes -subj /CN=localhost
openssl s_server -key /tmp/tls-fuzzer-key.pem -cert /tmp/tls-fuzzer-cert.pem -accept 31337 -www -debug
```

## Project Structure

- `src/tech/cybersword/tls/fuzzer/controller/`
  - `TLSController.java`: main entry point. Starts the browser dashboard, launches fuzzer jobs, reports status.
- `src/tech/cybersword/tls/fuzzer/client/`
  - `TLSClient.java`: raw TCP socket sender/receiver for generated TLS byte arrays.
- `src/tech/cybersword/tls/fuzzer/generator/`
  - `TLSProtocolDataGenerator.java`: current main RFC/vector generator.
  - `TLSFuzzVector.java`: immutable name/RFC/description/data holder for generated vectors.
  - `TLS12TestDataGenerator.java`: TLS 1.2 compatibility wrapper and older examples.
  - `TLS13TestDataGenerator.java`: TLS 1.3 compatibility wrapper and older examples.
  - `TLS13TestValidDataGenerator.java`: older TLS 1.3 generator copy.
  - `TLSExtensionDataGenerator.java`: older extension fixture/random data helpers.
  - `RandomGenerator.java`, `TLSClientHelloDataGenerator.java`, `ITLSExtensionData.java`: older/partial generator helpers.
- `src/tech/cybersword/tls/fuzzer/dashboard/`
  - `BrowserDashboardServer.java`: built-in HTTP/optional HTTPS browser dashboard.
  - `FuzzerStatusRegistry.java`: concurrent in-memory status registry.
  - `FuzzerTestStatus.java`: immutable status model.
- `src/tech/cybersword/tls/fuzzer/ui/`
  - `TLSSystemTray.java`: AWT system tray integration, if supported.
  - `TLSDashboard.java`: Swing dashboard, hidden/no-op in headless environments.
- `src/tech/cybersword/tls/fuzzer/common/`
  - `CommonProperties.java`: reads project properties.
- `src/tech/cybersword/tls/fuzzer/util/`
  - Utility classes for logging, random bytes, array concat, hex conversion, properties, etc.
- `src/test/java/tech/cybersword/tls/fuzzer/`
  - JUnit tests for status tracking and TLS vector generation.
- `pics/`
  - UI/readme images.
- Root SBOM files:
  - `tech.cybersword.tls.fuzzer.sBOM.json`
  - `tech.cybersword.tls.fuzzer.sBOM.xml`
  - These are regenerated by `mvn package`.

## Current Fuzzer Coverage

The RFC byte-stream suite is generated from RFC 5246 and RFC 8446 structures plus illustrated examples from:

- `https://tls12.xargs.org/#open-all`
- `https://tls13.xargs.org/#open-all`
- `https://www.rfc-editor.org/rfc/rfc5246.txt`
- `https://www.rfc-editor.org/rfc/rfc8446.txt`

Current generated coverage includes:

- TLS 1.2 and TLS 1.3 ClientHello examples.
- Randomized extension/data ClientHello variants.
- Illustrated xargs TLS 1.2 and TLS 1.3 byte-stream examples.
- All one-byte TLS record content type selector values `0..255` combined with selected SSL/TLS version values and record length boundary values.
- All one-byte handshake type selector values `0..255` combined with uint24 length boundary values.
- Alert record probes for levels `0..2` and all one-byte alert descriptions `0..255`.
- RFC content type records: change cipher spec, alert, handshake, application data.
- TLS/SSL version probes including SSL 3.0 through TLS 1.3, boundary values, and GREASE-style `0x7f17`.
- TLS 1.2 and TLS 1.3 cipher suite offer vectors.
- TLS 1.3 named group/key_share vectors.
- TLS signature scheme vectors.
- ClientHello extension type vectors.
- Malformed length vectors.

Fully enumerating every possible TLS byte stream is impossible because TLS includes variable-length opaque fields up to 2^16 and 2^24 bytes. The current approach covers all one-byte header selectors and a broad set of RFC-defined enum and boundary values.

## Operational Notes

- The fuzzer writes many `TLSFuzzer_*.log.*` files in the project root. These are generated artifacts and are ignored by `.gitignore`.
- `mvn package` regenerates the SBOM JSON/XML files in the project root.
- Running the fuzzer against a closed target port produces many `Connection refused` messages. Start a TLS target first or change `tls.host` / `tls.port`.
- Current browser dashboard `/api/vectors` can be large because the header catalog is broad. The HTML page renders only the first visible slice to keep the browser responsive.
- Preserve existing dirty work unless explicitly asked to revert it.
